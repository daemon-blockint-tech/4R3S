ARES Auditor is an **autonomous Solana program security auditor**. It runs a LangGraph pipeline that loads program source, recalls prior security knowledge, analyzes the target in parallel, and produces a structured audit report.

## What ARES does

Every audit follows the same graph:

```
intake → load-source → recall → analyze (parallel) → merge → verify → remember → report
```

| Phase | Purpose |
| ----- | ------- |
| **Intake** | LLM parses your request into a structured target, depth, and concerns. |
| **Load source** | Reads `.rs` and Anchor IDL files into context (bounded by budget). |
| **Recall** | Pulls relevant knowledge from Crystalline memory and optional Supabase/Neo4j. |
| **Analyze** | Four analyzers run in parallel: on-chain, static (Semgrep), heuristic (LLM), optional CUA. |
| **Merge** | Dedupes and ranks findings by severity. |
| **Verify** | Skeptical critic pass drops false positives. |
| **Remember** | Persists useful fragments to durable knowledge (when configured). |
| **Report** | Markdown report with severity matrix, coverage, and analyzer status. |

<Note>
  ARES runs fully **offline** with only `OPENROUTER_API_KEY` set. Supabase, Neo4j, Postgres checkpointing, and embeddings are optional enhancements.
</Note>

## Products in this repository

The `4R3S` monorepo ships two products:

- **ARES Auditor** (defensive) — what this documentation covers. The shipping agent lives in root `src/`.
- **ARES-Sec** (offensive) — separate authorized pentest framework in `apps/ares-sec/`. Not covered here.
